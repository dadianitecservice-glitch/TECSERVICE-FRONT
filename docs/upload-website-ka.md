# TECSERVICE — საიტის ატვირთვა და Facebook-ზე გაზიარება

ეს პაკეტი შეიცავს ასატვირთად გამზადებულ საჯარო საიტს, ქართული და ინგლისური გვერდებით. ადმინპანელის მიერთება ბლოგის გაზიარებისთვის საჭირო არ არის.

## 1. რა უნდა აიტვირთოს

ZIP-ის მთავარ დონეზე მოთავსებულია `index.html`, `assets/`, `blog/`, `en/`, `services/` და საიტის სხვა მზა გვერდები. არქივში არ არის პროგრამის საწყისი კოდი, `.git`, `node_modules`, `.env`, სერვერის გასაღებები ან მომხმარებელთა მონაცემთა ბაზა.

1. შეინახეთ არსებული საიტის ფაილებისა და მოქმედი სერვერის კონფიგურაციის სარეზერვო ასლი.
2. ZIP-ის შიგთავსი ატვირთეთ `tecservice.ge`-ის საჯარო საქაღალდეში — იქ, საიდანაც ამჟამად მთავარი `index.html` გაიცემა. არ შექმნათ ზედმეტი `dist/` ან ZIP-ის სახელის მქონე ქვესაქაღალდე.
3. ატვირთეთ სრული პაკეტი და შეინარჩუნეთ საქაღალდეების სტრუქტურა. მხოლოდ მთავარი `index.html`-ის ან მხოლოდ ახალი ფოტოს ჩანაცვლება საკმარისი არ არის.
4. არ წაშალოთ და არ შეცვალოთ სერვერზე არსებული backend, `/api/` კონფიგურაცია, მონაცემთა ბაზა, მომხმარებელთა ატვირთული ფაილები, `.env`, TLS სერტიფიკატები ან სხვა ქვედომენები. ეს პაკეტი მხოლოდ საჯარო საიტის ფაილებისთვისაა.
5. თუ ჰოსტინგი მხარდაჭერას იძლევა, ახალი ვერსია ჯერ ცალკე დირექტორიაში განათავსეთ და შემოწმების შემდეგ გადართეთ მოქმედი საჯარო დირექტორია. ძველი ვერსია უკანდასაბრუნებლად შეინახეთ.

## 2. აუცილებელი სერვერის პარამეტრი

ბლოგის მისამართმა უნდა დააბრუნოს შესაბამისი სტატიის `index.html`, და არა მთავარი გვერდი. მაგალითად:

- `/blog/sd-card-photo-recovery-for-photographers/` → `blog/sd-card-photo-recovery-for-photographers/index.html`
- `/en/blog/sd-card-photo-recovery-for-photographers/` → `en/blog/sd-card-photo-recovery-for-photographers/index.html`

ბოლო შემოწმებისას რეალურ საიტზე ორივე საცდელი სტატიის მისამართი მთავარი გვერდის მონაცემებს აბრუნებდა. ამიტომ, თუ ფაილების ატვირთვის შემდეგაც იგივე დარჩა, ჰოსტინგის ადმინისტრატორმა უნდა გაასწოროს გვერდების მიწოდების წესი.

Nginx-ისთვის პროექტს ახლავს `docs/nginx-seo-routes.conf`. ეს არის შესათავსებელი ნიმუში და არა მოქმედი სერვერის კონფიგურაციის ბრმად ჩასანაცვლებელი ფაილი. არსებული TLS, API, უსაფრთხოების სათაურები და სხვა ქვედომენები უნდა შენარჩუნდეს. რეალური საჯარო დირექტორია ჰოსტინგის ადმინისტრატორმა უნდა მიუთითოს.

საჯარო სტატიკური გვერდებისთვის მნიშვნელოვანი პრინციპია:

```nginx
try_files $uri $uri/index.html =404;
```

არ უნდა მოქმედებდეს წესი, რომელიც ყველა სტატიის მისამართს მთავარ `/index.html`-ზე გადაამისამართებს. `nginx -t` უნდა დასრულდეს წარმატებით კონფიგურაციის გადატვირთვამდე. სხვა ვებ-სერვერზე საჭიროა მისი შესაბამისი წესი და არა Nginx-ის ფრაგმენტის ჩასმა.

## 3. რა უნდა შემოწმდეს ატვირთვის შემდეგ

გახსენით ორივე სტატია და გარეკანი საჯარო მისამართებზე:

- https://tecservice.ge/blog/sd-card-photo-recovery-for-photographers/
- https://tecservice.ge/en/blog/sd-card-photo-recovery-for-photographers/
- https://tecservice.ge/assets/blog/sd-card-photo-recovery.webp

სამივე მისამართი უნდა აბრუნებდეს წარმატებულ პასუხს (`200`). ფოტო უნდა გაიხსნას სურათად და არა შეცდომის ან მთავარი გვერდის სახით.

სტატიის საწყის HTML-ში, JavaScript-ის გაშვებამდე, უნდა იყოს:

- `og:url` და `canonical` — ამ კონკრეტული სტატიის მისამართი, შესაბამისი ენით.
- `og:type` — `article`.
- `og:title` — SD ბარათის სტატიის სათაური და არა მთავარი გვერდის სათაური.
- `og:image` — `https://tecservice.ge/assets/blog/sd-card-photo-recovery.webp`.
- `og:description` — სტატიის მოკლე აღწერა.

ეს ინფორმაცია მზა პაკეტში უკვე ჩაშენებულია. JavaScript-ით გახსნილი სწორი გვერდი თავისთავად არ ადასტურებს, რომ Facebook-საც სწორი საწყისი HTML მიეწოდება.

თუ ჰოსტინგს ან CDN-ს აქვს ქეში, განაახლეთ შეცვლილი გვერდებისა და გარეკანის ქეში. შემდეგ, თუ Facebook ისევ ძველ პრევიუს აჩვენებს, გამოიყენეთ [Facebook Sharing Debugger](https://developers.facebook.com/tools/debug/): ჩასვით კონკრეტული სტატიის სრული მისამართი და დააჭირეთ `Scrape Again`. საჭიროების შემთხვევაში შედით საკუთარ Facebook ანგარიშში. ამის შემდეგ შექმენით ახალი გაზიარების მცდელობა.

## მნიშვნელოვანი

ZIP-ის მომზადება ან Git-ზე კოდის ატვირთვა თავისთავად არ ნიშნავს, რომ საიტი უკვე განახლდა ჰოსტინგზე. Facebook-ზე საბოლოო შედეგი უნდა შემოწმდეს საჯარო ფაილებისა და სერვერის წესების განახლების შემდეგ. ეს ატვირთვა არ ააქტიურებს ადმინპანელს, რეალურ მომხმარებელთა მომსახურებას, SMS-ს ან გადახდებს.
